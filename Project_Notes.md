# Warframe Inventory Tracker — Project Notes

A running log of what's been built, decided, and researched across development. Useful as a reference for onboarding collaborators, remembering *why* something works the way it does, or picking a thread back up after time away.

---

## Origin

Started as a simple Electron app tracking a manually-entered inventory list against warframe.market prices (`v1.1.0`). Grew into a full companion app: farm-location lookup, a build-completion tracker, relic management with a recommendation engine, price history charting, and a proper release pipeline.

---

## Architecture at a Glance

- **Electron** app — `main.js` (main process: all API calls, caching, file storage) ↔ `preload.js` (contextBridge) ↔ `dashboard.js`/`dashboard.html` (renderer, no direct Node access).
- **Data storage**: flat JSON files in `userData` — `inventory.json`, `buildTracker.json`, `relicInventory.json`, plus cache files (`itemCache.json`, `farmDataCache.json`, `priceHistoryCache.json`, `relicDropCache.json`) and `auto-backup.json`.
- **External data sources**:
  - `api.warframe.market` (v2 for live orders, v1 for price history/statistics — v1 requires specific headers including `Referer` or it 403s)
  - `api.warframestat.us` (WFCD) — item catalog, farm/component data, images
  - `drops.warframestat.us` — relic reward tables by tier/name/refinement state
- A `bundled-relic-cache.json` ships with the app (generated by `scripts/build-relic-cache.js`) so relic lookups work instantly on first launch, before any live refresh.

## Major Features Built

### Price Tracker
- Add items by name/slug with warframe.market autocomplete.
- Sortable table: name, type, rarity, vaulted, set, quantity, price, total, last updated.
- Rarity tier visuals: gold/silver/bronze row tinting for components (computed from relic drop-chance data, not warframe.market tags — see "Rarity Tier System" below), true rarity coloring for mods (warframe.market tags do carry rarity for mods, just not for Prime components).
- Blue-tinted, white-bordered rows for combined "Sets."
- Click item name → farm-info modal (drop locations). Click price → 90-day price/volume history chart.

### Build Tracker
- Track Warframe/weapon sets; card-based UI with per-set component checklists.
- Checking a Prime component's box adds it to the price tracker (constructs the warframe.market slug directly — no lookup needed since the naming convention is standard, with known exceptions handled: the "Blueprint" component itself never gets a second `_blueprint` suffix, Warframe non-blueprint parts do, weapon non-blueprint parts don't).
- Checking a non-Prime (base frame) component just marks it locally (`obtainedParts` on the tracked-set entry) — no market call, since base parts aren't tradable.
- "Combine Set" button appears once all Prime components are owned — consumes the components, adds one "{Set} Set" entry, fetches its real market price.
- "I've Crafted This — Remove" button appears instead, for base (non-Prime) sets once complete, since there's no market "Set" to combine into.
- Filters: All/Warframes/Weapons, and Any/Prime Only/Non-Prime Only (two independent dimensions).
- Archwing/Archgun/Archmelee badge overlay on card images (custom-sourced icon, positioned via a scoped `.image-container` wrapper).

### Relics
- Card-grid inventory (image + name + quantity), sorted by tier (Lith → Meso → Neo → Axi).
- Fast batch entry: autocomplete with arrow-key navigation and Enter-to-add, built for logging many drops after a play session or bulk-importing an existing collection.
- Click a relic → see its full reward table at Intact tier.
- **Recommendations** (own page, reachable via sidebar sub-item that appears once used):
  - **Tracked Set Gaps**: cross-references owned relics against build-tracker gaps; tells you which relic, at which minimum refinement tier, to crack. Grouped by set (with set image) or by relic — toggle between views.
  - **Discover New Sets**: scans owned relics against *every* Prime Warframe/weapon in the game (not just tracked ones); surfaces anything where owned relics could cover ≥75% (3/4) of required components. One-click "Track this Set."
  - Farm-info modal highlights relics you already own, with quantity, next to their drop-chance entry.

### Backup / Data Safety
- Manual Export/Import (user-chosen file location via native dialog) — `inventory.json` + `buildTracker.json` only (caches deliberately excluded; they're fully regenerable and a stale cache is worse than no cache).
- Automatic backup on every app close (`auto-backup.json`, silent, `userData`-local).
- One-click "Restore Last Auto-Backup," tucked into Settings (not a primary action) since it's a rare/emergency tool.

### Settings
A Discord-style full-screen overlay (not a small popover — deliberately chosen for room to grow). Currently: Export/Import backup, Restore Last Auto-Backup, Recompute Rarity Tiers, Backfill Relic Images, Clear Farm Data Cache, Update All Relic Data. **Flagged for visual cleanup before next release** — functional but needs polish.

### Misc
- App version displayed in sidebar (reads `app.getVersion()` live from `package.json` — groundwork for future update-checking).
- Sticky page headers (price/quantity summary, add-item controls) so they stay visible while scrolling long lists.

## Rarity Tier System — How It Actually Works

This took several iterations to get right, worth documenting the final logic:

1. Warframe.market's item **tags never carry rarity for Prime components** (only category info: `component`, `prime`, `warframe`, `blueprint`, etc.). They *do* carry rarity for mods (`rare`, `uncommon`, `common` appear in mod tags).
2. WFCD's own per-component `rarity` field (Common/Uncommon/Rare) is too coarse — it reflects the reward-slot tier *within a single relic*, not the component's overall scarcity across all its possible relics.
3. **The actual signal**: drop-chance percentages cluster into exactly three values game-wide — 10% (rarest), 20% (middle), 25.33% (most common) — confirmed by survey across 5 different Prime frames with zero outliers.
4. **Final algorithm**: for each component, summarize its raw drops (collapsing refinement-tier duplicates to one best-odds entry per relic — this step is essential; skipping it and computing the median on raw duplicated data was an early bug that misclassified Burston Prime Barrel), then take the **median** of the summarized chances, then map to a tier via fixed thresholds (`≤15` → gold, `≤22.665` → silver, else → bronze — the midpoints between the three real values, so any edge case rounds toward the rarer tier).
5. Mapped to display labels matching mods: gold→Rare, silver→Uncommon, bronze→Common.
6. Computed once at add-time and stored on the inventory item (`item.tier`); a "Recompute Rarity Tiers" button in Settings backfills existing items after logic changes.

## Bugs Found & Fixed (Worth Remembering)

- **Type-string inconsistency**: `inferTypeFromTags()` (warframe.market-tag-based) and WFCD's own `type` field use different vocabularies (`"Warframe Part"` vs. bare `"Warframe"`, `"Rifle"`, `"Arch-Gun"`, etc.), depending on which code path created a record. Several functions (`getEndpointForType`, `chanceToTier`'s caller, `checkOffComponent`'s slug-suffix logic, the mod-vs-warframe classification) were hardened from exact-string checks to `.includes(...)` checks to tolerate this. **Also fixed at the source**: `inferTypeFromTags` checked `"warframe"`/`"weapon"` tags before `"mod"`, so any Warframe-specific or weapon-specific mod (e.g., Mesa's Waltz) was misclassified as `"Warframe Part"` — reordered so `"mod"` is checked first.
- **Relic name-suffix mismatches**: farm-data drop locations say `"Lith A12 Relic"`; the relic inventory stores `"Lith A12"` (no suffix). Any cross-referencing between the two needs to strip `" Relic"` before comparing.
- **Slug construction for the Blueprint component**: appending `_blueprint` to a component already named "Blueprint" doubles the suffix (`..._blueprint_blueprint`) — special-cased.
- **Relic casing on fast entry**: typing quickly and hitting Enter (skipping the autocomplete suggestion) skipped name normalization, so the tier-icon lookup (case-sensitive) silently failed. Fixed with a `normalizeRelicName()` pass before any downstream lookup.
- **Duplicate/leftover code from iterative rewrites**: several bugs traced back to two versions of the same function/variable existing in the file at once (JS silently uses whichever comes last, or throws a redeclaration error) — a recurring lesson: when a function gets substantially rewritten multiple times in one session, verify the *old* version was actually replaced, not left alongside the new one.
- **CSS stacking contexts**: adding `position: relative` to nested card elements (for absolute-positioned badges) can break sibling `position: fixed` modals that rely on z-index to stay on top, even with an explicit z-index set — resolved by pushing modal z-index to an overwhelming value (`9999`) rather than fighting the stacking math precisely.
- **`electron-builder`'s GitHub auto-publish**: known race condition against GitHub's eventually-consistent API creates duplicate draft releases with mangled tags when publishing multiple artifact groups back-to-back. Worked around for now by building locally (`npm run build`, no publish flag) and uploading releases manually through the GitHub website. A real upstream fix exists in newer `electron-builder` versions — worth revisiting.

## Distribution & Release Process

- Public GitHub repo, MIT licensed.
- Versioned releases via GitHub Releases (not the Microsoft Store — deliberate choice, since transparency-via-public-source-code was judged sufficient trust-building for a friends-and-hobbyist audience at this stage).
- Windows SmartScreen will flag the unsigned installer; this is expected and communicated in release notes ("click More info → Run anyway").
- Release history: `v1.1.0` (original price tracker) → `v2.0.0` (farm data, build tracker, price history) → `v2.1.0`/`v2.1.1` (relic system, various fixes) → `v2.2.0` (Discover New Sets, relic highlighting, Prime filter, README).

## Researched & Deliberately NOT Pursued

- **Reading game files / process memory for automatic inventory sync**: investigated thoroughly. Your actual inventory lives server-side, not in any local file. A real (but undocumented, currently-suspended) personal API exists (`api.warframe.com/api/inventory.php`, used by the official mobile companion app), and a community tool (`Sainan/warframe-api-helper`) uses it — but authenticates by reading the game's *process memory* to extract account credentials/session tokens, which its own maintainers describe as "theoretically bannable." Decision: not worth building into this app; the risk category (reading live game memory, handling account auth) is fundamentally different from everything else here (which only calls public, designed-for-third-parties APIs). If ever revisited, the safe version would be treating `warframe-api-helper.exe` as an external, already-vetted tool and just building an *importer* for its output — keeping the risky part fully outside this codebase.
- **Full recommendation engine using WFCD's `/wfinfo/filtered_items`**: superseded by `drops.warframestat.us`'s per-relic, per-refinement-state endpoint, which turned out to be a cleaner, more directly useful data source for the "what tier should I refine to" question.

## Roadmap / Not Yet Built

- **Settings panel visual cleanup** — flagged as needed before the next release; functional but visually rough.
- **Portfolio value snapshots over time** — small, independent; snapshot `totalPlat` on app launch (not on a timer, since usage is session-based and a timer would just show flat lines between sessions).
- **`electron-updater`** — in-app update checking against GitHub Releases. Needs pairing with a fix for the duplicate-draft-release bug above, and a real two-version test cycle (ship A, ship B, confirm A detects and installs B) before it can be trusted.
- **Code signing (EV certificate)** — priced out (DigiCert/Sectigo/SSL.com/Certum; requires a hardware token or cloud HSM). Deferred until SmartScreen friction becomes a real problem for a wider audience — not worth the ongoing cost for a friends-and-hobbyist user base yet.
- **macOS build target** — low-risk, likely-easy experiment (Electron code should be cross-platform already; just needs a `"mac"` target block in `package.json`, a `.icns` icon, and a build run *on* a Mac). Deliberately deprioritized below other work but not abandoned.
- **Mobile (iOS/Android)** — explicitly deprioritized; decided it's not valuable right now. If ever pursued: Capacitor-wrapping a rebuilt web-only version was the agreed first step (not a full native rewrite), with the whole `main.js` backend needing to be restructured into shared, dependency-injected `/core` logic + thin per-platform adapters (Electron's fs/axios/IPC vs. a browser's IndexedDB/fetch) so `dashboard.js`/`dashboard.html` could be reused as-is across platforms.
- **Repo size**: `bundled-relic-cache.json` (~3.7MB) bloats git history on every regeneration since it's a large, non-diffing JSON blob. Acceptable tradeoff for now (prioritizing new-user setup simplicity); Git LFS or excluding it from version control entirely (generating it only at build time) are the two known fixes if it becomes a real problem.
- **Sequential vs. parallel data fetching**: Build Tracker and Relics pages currently `await` each card's data one at a time, causing an occasional visible loading flash on cold cache. Not urgent; worth revisiting once more features stack up and it becomes a bigger drag.

## Known Non-Issues (Investigated, Confirmed Working As-Is)

- **Vendor/syndicate-acquired mods** (e.g., Mesa's Waltz): initially assumed these had no usable farm data. Verified directly — WFCD's data *does* cover them, just repurposing the `location`/`chance`/`rarity` shape to describe syndicate rank + standing cost instead of a mission. Displays correctly already; no fix needed. (A stale cached "no data" result from an early test made this look broken until the cache was cleared — added a troubleshooting note in Settings for this exact situation.)
